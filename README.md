## The Problem

AI tools like ChatGPT and Claude generate working web apps in minutes. The app runs. It looks fine. But it ships with no authentication on API routes, hardcoded API keys, SQL queries built with string formatting, no rate limiting on login endpoints, and tokens stored in localStorage.

These are not code bugs. They are system design failures — the kind that do not show up in a linter or a basic code review. They show up in a breach.

Vibe Code Security Scanner finds them automatically and tells you exactly how to fix each one using AI-generated, context-aware remediation.

---

## Key Capabilities

- **20 security checks** across Python, HTML, and JavaScript files
- **AST-based analysis** — parses Python code into a syntax tree for precise, low false-positive detection
- **System design focus** — catches missing authentication, rate limiting, and access control, not just insecure code patterns
- **AI-powered remediations** — every finding gets a contextual fix generated by Llama 3.1 via Groq, specific to the file and line number
- **Backend / frontend split** — results separated into Python issues and HTML/JS issues
- **Three-page web application** — landing page, scanner, and results with full scan history
- **CI/CD pipeline** — 5 automated security jobs run on every push

## What it detects

### Backend — Python

- Hardcoded secrets and API keys
- SQL injection via string formatting instead of parameterised queries
- Missing authentication on FastAPI and Flask routes
- Debug mode enabled in production
- Missing input validation on route parameters
- Sensitive data returned in API responses
- Stack trace exposure in exception handlers
- Environment variables hardcoded in source
- Missing rate limiting on sensitive endpoints
- Missing security headers on responses
- Exposed admin or debug endpoints
- IDOR risk — data fetched without ownership checks
- Missing file upload validation
- Row level security missing on database queries
- Missing HTTPS enforcement
- Missing 2FA on authentication routes
- Missing server-side validation on POST/PUT routes
- Outdated dependencies with known CVEs

### Frontend — HTML and JavaScript

- API keys hardcoded in client-side code
- Tokens stored in localStorage or sessionStorage

## Quick Start

**Prerequisites:** Python 3.8+, Git, Groq API key (free at console.groq.com)

```bash
# Clone the repo
git clone https://github.com/KuruJPerera/vibe-code-security-scanner.git
cd vibe-code-security-scanner

# Install dependencies
pip install -r requirements.txt

# Add your Groq API key
echo "GROQ_API_KEY=your-key-here" > .env

# Start the scanner
uvicorn app.main:app --reload
```

Open **http://localhost:8000**, paste a GitHub repo URL, and click Run Scan.

> [!NOTE]
> The scanner clones the target repo to a temporary directory, analyses it, generates AI remediations, then deletes the clone. Nothing is stored except findings.

---

## How it works

```
Landing page → Scanner page → POST /scan → Clone repo → Run 20 checks
     → Save to SQLite → Redirect to Results page → Load findings
     → POST /remediate (per finding) → Groq generates fix → Display inline
```

## CI/CD Security Pipeline

Every push runs five automated security jobs in parallel:

- **Bandit** — Python SAST scanning for insecure functions and hardcoded secrets
- **Semgrep** — OWASP Top 10 rules across the codebase
- **Safety** — dependency CVE scanning
- **Gitleaks** — secret scanning across full git history
- **pytest** — 6 unit tests covering core check functions
